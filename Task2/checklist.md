# Проверочный лист безопасности для бизнес-систем PropDevelopment

# Ключевые особенности системы с точки зрения безопасности:
1.	Обработка персональных данных. Во многих приложениях (client-mart-app, client-crm-app, tenant-core-app) происходит сбор, хранение и обработка персональных данных — критический элемент с точки зрения закона (ФЗ-152).
2.	Интеграции с госорганами и платёжными системами. Высокие риски при компрометации или недоступности ключей/токенов.
3.	Онлайн-сделка с юридической значимостью. Требуется надёжная аутентификация, логирование и защита данных.
4.	Децентрализованная архитектура (много микросервисов и БД). Повышенные риски несанкционированного доступа, сложность контроля доступа и шифрования.
5.	Наличие аналитики и BI. Возможность утечек внутренних метрик и стратегической информации.
6.	Active Directory и централизованная аутентификация. Потенциальная уязвимость, если не реализована многофакторная аутентификация (MFA).

## Почему выбран именно этот состав разделов

Опираемся **на две главные проблемы бизнеса**:

*Нарушен контроль данных*
→ выбранный фокус: **Data Governance, доступ, целостность данных, аудит, API-безопасность**

*Проблемные интеграции с системами управляющих компаний*
→ фокус: **контроль взаимодействия через API, управление внешними доступами**

А также на планы компании:

* развитие сервисов на **основе данных** (BI, AI, ML)
* внедрение **онлайн-сделки** как юридически значимого процесса
* рост нагрузки гибридной инфраструктуры → **непрерывность и восстановление**

Поэтому включены разделы:

| Раздел                                | Зачем нужен PropDevelopment                                      |
| ------------------------------------- | ---------------------------------------------------------------- |
| Управление доступом (IAM)             | Решить проблему множественных точек регистрации и ошибок доступа |
| Безопасность данных / Data Governance | Предотвратить утечки ПДн и ошибки с отображением чужих данных    |
| API-безопасность и партнёры           | Закрыть риски доступа между управляющими организациями           |
| Аудит и мониторинг                    | Повышение качества данных, контроль сделок и ПДн                 |
| Резервирование и восстановление       | Минимизировать ущерб инцидентов                                  |
| Инфраструктура и сегментация          | Снизить область распространения атаки                            |
| Управление инцидентами                | Быстро реагировать на угрозы, как в недавнем кейсе конкурента    |
